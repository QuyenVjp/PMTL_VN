# API — Coding Constitution

> Scope: `apps/api/` only.
> Root rules: `AGENTS.md` at repo root.
> Stack: NestJS 11 + TypeScript + Prisma + PostgreSQL + Zod + pino.

---

## 1. Module Structure

Every domain module lives under `src/modules/{domain}/` or `src/platform/{concern}/`:

```
modules/{domain}/
├── {domain}.module.ts       ← @Module — wires controllers, services, imports
├── {domain}.controller.ts   ← HTTP surface only; no logic
├── {domain}.service.ts      ← business logic authority
├── {domain}.repository.ts   ← Prisma queries (optional; for complex data access)
├── {domain}.schemas.ts      ← Zod validation schemas (one per module)
└── {domain}.types.ts        ← shared TypeScript types (optional)
```

**Platform modules** (`src/platform/`) own control-plane concerns:
`storage`, `audit`, `sessions`, `feature-flags`, `rate-limit`, `health`, `metrics`.

**Rules:**
- Business logic lives in **services**, never in controllers or repositories.
- Controllers parse + validate input (Zod), call service, return response. That's all.
- Repositories hold Prisma query logic when a service has > 3 distinct query patterns.
- Modules declare their own providers and export only what other modules need.

## 2. Input Validation — Zod (Mandatory)

All user input MUST be validated with Zod before it reaches service logic.

```typescript
// {domain}.schemas.ts
import { z } from "zod";

export const createItemSchema = z.object({
  title:       z.string().min(1).max(200).trim(),
  description: z.string().max(2000).trim().optional(),
  status:      z.enum(["DRAFT", "PUBLISHED"]).default("DRAFT"),
});

export type CreateItemInput = z.infer<typeof createItemSchema>;
```

```typescript
// {domain}.controller.ts
@Post()
create(@Body() body: Record<string, unknown>, @CurrentUser() user: AuthenticatedUser) {
  return this.service.create(createItemSchema.parse(body), user.id);
}
```

**Rules:**
- Schema files are named `*.schemas.ts`, one per module.
- Never trust `@Body()` typed directly — always use `Record<string, unknown>` + `schema.parse()`.
- Use `.trim()` on all string fields.
- Expose `z.infer<typeof schema>` as the typed input to service methods.

## 3. Error Handling

Use the canonical error types from `src/common/errors/app-error.ts`:

| Error Class | HTTP | When to throw |
|---|---|---|
| `NotFoundError` | 404 | Record not found by publicId |
| `ConflictError` | 409 | Slug/unique constraint violation |
| `ForbiddenError` | 403 | User lacks permission for this record |
| `BadRequestException` (NestJS) | 400 | Invalid input not caught by Zod |

```typescript
const item = await this.prisma.item.findUnique({ where: { publicId } });
if (!item) throw new NotFoundError("Item", publicId);
```

**Log all errors with pino context:**
```typescript
this.logger.error({ publicId, userId, err }, "Failed to update item");
```

Never swallow errors with empty `catch {}` blocks.

## 4. Auth — Guards & Decorators

Global guards run in this order for every request:
1. `AuthGuard` — verifies JWT cookie (`pmtl_access`); skip with `@Public()`
2. `RolesGuard` — checks user role; skip by using `@Roles()` (no args)
3. `RateLimitGuard` — per-route throttle via metadata

**Standard patterns:**

```typescript
// Protected — ADMIN or SUPER_ADMIN only
@Controller("admin/resource")
@UseGuards(RolesGuard)
@Roles("ADMIN", "SUPER_ADMIN")
export class AdminResourceController { ... }

// Public endpoint inside a protected controller
@Get(":publicId/content")
@Public()
@Roles()   // ← overrides class-level @Roles with empty = allow all
async content(...) { ... }

// Authenticated but any role
@Get("me")
// no @Roles → RolesGuard passes (requiredRoles.length === 0)
async getMe(@CurrentUser() user: AuthenticatedUser) { ... }
```

**Rules:**
- Never bypass `AuthGuard` for admin routes except true public resources (media content).
- Use `@CurrentUser()` to get the authenticated user — never read from `request.user` manually.
- Class-level `@Roles(...)` is inherited by all methods; override per-method when needed.

## 5. Public IDs

- Every record exposed via API must have a `publicId` generated by `nanoid(21)`.
- **Never** expose the internal database `id` (integer or cuid) in API responses.
- `publicId` is used as the URL param for all CRUD routes (`:publicId`).
- Store `publicId` in a `@unique @map("public_id")` column in Prisma.

```typescript
import { nanoid } from "nanoid";
const publicId = nanoid(21);
```

## 6. Response Format

All responses go through `ResponseInterceptor` which wraps into:
```json
{ "data": <T>, "meta": { "timestamp": "...", "requestId": "..." } }
```

Service methods return **plain data** — the interceptor wraps automatically.
Controllers return the service result directly. Do not manually wrap `{ data: ... }` in controllers.

**Exception:** binary/stream responses (`StreamableFile`, `res.redirect()`) bypass the interceptor.

## 7. Prisma Usage

```typescript
// In services — always use PrismaService (injected)
constructor(private readonly prisma: PrismaService) {}

// Prefer select over findMany with no projection
const items = await this.prisma.item.findMany({
  where,
  orderBy: { createdAt: "desc" },
  select: { publicId: true, title: true, status: true },
});

// Always use transactions for multi-table writes
await this.prisma.$transaction([
  this.prisma.item.update(...),
  this.prisma.auditLog.create(...),
]);
```

**Rules:**
- Never use `prisma.item.findMany()` without a `select` or `include` in production paths — avoid accidental full-row fetches.
- Use `directUrl` (port 55432 locally) for migrations; use runtime `DATABASE_URL` for queries.
- Dev schema changes: `prisma db push` (safe for local drift).
- Production schema changes: `prisma migrate dev` → commit migration file.
- Never run `prisma migrate reset` on a database with real data.

## 8. Audit Logging

All write paths (create, update, delete, status change) that affect user-visible content **must** be audit-logged.

```typescript
// After the write, log to AuditService
await this.auditService.log({
  actorId:    userId,
  action:     "content.item.publish",
  resourceId: publicId,
  meta:       { title: item.title },
});
```

**Minimum audit coverage:**
- Content publish/unpublish/archive
- User role changes
- User block/unblock
- Feature flag toggles
- Media asset delete

## 9. Config & Secrets

All config comes from `ConfigService` (injected). Never read `process.env` directly in module code.

```typescript
// ✓ correct
constructor(private readonly config: ConfigService) {}
const secret = this.config.jwtAccessSecret;

// ✗ forbidden
const secret = process.env.JWT_ACCESS_SECRET; // in module code
```

Env validation lives in `src/common/config/config.schemas.ts` (Zod).

## 10. File Layout Conventions

| Pattern | Rule |
|---|---|
| Controller route prefix | Matches module path: `admin/content/media-library` |
| Schema file | `*.schemas.ts` — one per module, all Zod schemas together |
| Service method names | `list`, `get`, `create`, `update`, `delete`, `publish`, `unpublish` |
| Repository method names | `findMany`, `findById`, `findByPublicId`, `create`, `update`, `delete` |
| Global prefix | `api` — set in `main.ts`; do not set per-module |
| Static asset serving | `app.useStaticAssets(root, { prefix: "/media" })` — bypasses global prefix |

---

## 11. What Is Forbidden

| Anti-pattern | Why |
|---|---|
| Business logic in controllers | Controller is HTTP surface only |
| Direct `process.env` in module code | Use `ConfigService` |
| Exposing internal DB `id` in responses | Use `publicId` only |
| `@Body() body: SomeDto` without Zod parse | NestJS DTOs bypass Zod; stick to `Record<string, unknown>` + `schema.parse()` |
| Empty `catch {}` blocks | Silently swallows errors, breaks observability |
| `prisma.item.findMany()` without `select` on hot paths | Accidentally fetches full rows including sensitive fields |
| `migrate reset` on shared/prod data | Data loss |
| Hardcoded admin user IDs or secrets | Security violation |
| `console.log` in production code | Use `this.logger` (pino) with structured context |
| Multiple `@Module` registrations of the same provider | Causes circular DI and duplicate singletons |

## 12. Naming Conventions

| Item | Convention | Example |
|---|---|---|
| Module class | `PascalCase` + `Module` | `AdminMediaLibraryModule` |
| Controller | `PascalCase` + `Controller` | `AdminMediaLibraryController` |
| Service | `PascalCase` + `Service` | `AdminMediaLibraryService` |
| Schema const | `camelCase` + `Schema` | `createCollectionSchema` |
| Prisma model field | `camelCase` (mapped to `snake_case`) | `collectionType` → `@map("collection_type")` |
| Route params | `publicId` (always) | `@Param("publicId") publicId: string` |
| Vietnamese API messages | Full diacritics | `"Tài liệu không tồn tại"` |
