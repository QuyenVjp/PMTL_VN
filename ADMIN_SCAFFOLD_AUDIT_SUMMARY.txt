## Queries.ts Implementation Checklist

### For Each Feature Folder:

```
apps/admin/src/features/{feature}/
├── query-keys.ts         # Factory functions per TanStack Query v5
├── queries.ts            # useQuery hooks + raw query functions
├── mutations.ts          # useMutation hooks + invalidation logic
└── types.ts              # Request/response types (if not in shared)
```

### Required Query Functions (All)

- **List query**: `use{Feature}List(filters?)` with pagination, sorting, filtering support
- **Detail query**: `use{Feature}Detail(id)` for single resource
- **Invalidation key factory**: `{feature}Keys` with `list(filters)`, `detail(id)` variants

### Required Mutation Functions (By Feature)

| Feature | Create | Update | Delete | Publish | Custom |
|---------|--------|--------|--------|---------|--------|
| Posts | ✓ | ✓ | ✓ | ✓ unpublish | — |
| Guides | ✓ | ✓ | ✓ | ✓ | — |
| Daily Practice | ✓ | ✓ | ✓ | — | workspace publish |
| Little House | ✓ | ✓ | ✓ | — | workspace publish |
| Life Release | ✓ | ✓ | ✓ | — | workspace publish |
| Media Library | ✓ | ✓ | ✓ | — | workspace publish, setFeatured |
| Media | ✓ upload | ✓ metadata | ✓ | — | — |
| Community Posts | — | status only | ✓ | — | hide/show |
| Guestbook | — | ❌ NO EDIT | ✓ | — | approve/reject |

**Legend**: ✓ = required, ❌ = explicitly forbidden, — = not applicable

## High-Impact Constraints

| Constraint | Features Affected | Implementation Rule |
|-----------|------------------|-------------------|
| Query key factory pattern | All (9 features) | Use `{feature}Keys` factory objects; never hardcode string keys in components |
| Publish → public cache trigger | Posts, Guides, all workspaces | Mutations.ts must call `platform/cache` webhook after publish success |
| Dashboard cascade invalidation | Posts, Guides, Moderation reports | Publish/approve/reject mutations must invalidate `['admin-dashboard', 'recent-posts']` and `['admin-dashboard', 'pending-reports']` |
| Media deletion coordination | Media, Media Library | Delete must check asset linkage in media-library collections before allowing |
| Guestbook no-edit | Guestbook | NO `updateEntry()` mutation; detail view read-only |
| Community flags required | Community Posts, Guestbook | Wrap UI in feature flag guards; queries/mutations callable regardless |
| Role narrowing mismatch | Content (editor+), Community (moderator+) | Backend API must enforce; frontend admin page shows as admin+ |

## Invalidation Rules Summary

### Default Pattern (Create/Update)
```
queryClient.invalidateQueries({ queryKey: [{feature}Keys.lists()] });
queryClient.invalidateQueries({ queryKey: [{feature}Keys.detail(id)] });
```

### Publish Pattern (Content Only)
```
queryClient.invalidateQueries({ queryKey: [{feature}Keys.lists()] });
queryClient.invalidateQueries({ queryKey: [{feature}Keys.detail(id)] });
queryClient.invalidateQueries({ queryKey: ['admin-dashboard', 'recent-posts'] });
// + triggerPublicCacheInvalidation() → platform/cache webhook
```

### Moderation Decision Pattern (Community)
```
queryClient.invalidateQueries({ queryKey: ['admin-community-posts', 'list'] });
queryClient.invalidateQueries({ queryKey: ['admin-community-post', 'detail', id] });
queryClient.invalidateQueries({ queryKey: ['admin-dashboard', 'pending-reports'] });
// + if target is in another workspace, invalidate that too
```

### Workspace Publish (Daily Practice, Little House, Life Release, Media Library)
```
queryClient.invalidateQueries({ queryKey: [{workspace}Keys.all] }); // Invalidate ALL subkeys
queryClient.invalidateQueries({ queryKey: ['admin-dashboard'] }); // Dashboard cascade
// + triggerPublicCacheInvalidation() for public surface
```

## Common Pitfalls to Avoid

### ❌ DON'T

```typescript
// Hard-coded query keys in mutations
onSuccess: () => {
  queryClient.invalidateQueries({ queryKey: ['admin-posts'] });
}
```

### ✅ DO

```typescript
// Use factory from query-keys.ts
import { postsKeys } from './query-keys';

onSuccess: () => {
  queryClient.invalidateQueries({ queryKey: postsKeys.lists() });
}
```

---

### ❌ DON'T

```typescript
// Invalidate everything on publish
onSuccess: () => {
  queryClient.invalidateQueries();
}
```

### ✅ DO

```typescript
// Precise invalidation per canonical rules
onSuccess: (data) => {
  // Invalidate own workspace
  queryClient.invalidateQueries({ queryKey: postsKeys.lists() });
  queryClient.invalidateQueries({ queryKey: postsKeys.detail(data.id) });
  // Invalidate dashboard cascade
  queryClient.invalidateQueries({ queryKey: ['admin-dashboard', 'recent-posts'] });
  // Trigger public cache invalidation (platform/cache webhook)
  await apiClient.post('/internal/revalidate', { source: 'post-publish', id: data.id });
};
```

---

### ❌ DON'T

```typescript
// Delete media without checking linkage
onSuccess: () => {
  queryClient.invalidateQueries({ queryKey: mediaKeys.lists() });
}
```

### ✅ DO

```typescript
// Check media-library references before delete
mutationFn: async (assetId) => {
  const linkedCollections = await apiClient.get(`/api/admin/content/media-library/collections?assetId=${assetId}`);
  if (linkedCollections.length > 0) {
    throw new Error(`Asset used in ${linkedCollections.length} collections`);
  }
  return apiClient.delete(`/api/content/media/${assetId}`);
},
onSuccess: (data, assetId) => {
  queryClient.invalidateQueries({ queryKey: mediaKeys.lists() });
  queryClient.invalidateQueries({ queryKey: mediaKeys.detail(assetId) });
  // Also invalidate media-library if asset removal affects featured/collections
  queryClient.invalidateQueries({ queryKey: ['admin-media-library'] });
};
```

## Feature Flag Verification

Before implementing community pages, verify flags exist:

```typescript
// In feature component
import { useFeatureFlag } from '@/lib/feature-flags';

export function CommunityPostsPage() {
  const { isEnabled: communityPostsEnabled } = useFeatureFlag('community.post.enabled');
  
  if (!communityPostsEnabled) {
    return <FeatureFlagDisabledAlert />;
  }
  
  return <AdminCommunityPosts />;
}
```

Feature flags **do not block** query/mutation implementation — they gate UI rendering. Queries & mutations must be queryable regardless of flag status (for programmatic checks, admin dashboards, etc.).
